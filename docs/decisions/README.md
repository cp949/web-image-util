# 아키텍처 결정 기록(ADR)

이 폴더는 되돌리기 비용이 큰 설계 결정을 기록한다. 파일명은 `ADR-XXXX-<slug>.md`이고 번호는
기존 최대 번호 다음을 쓴다.

## 템플릿

```markdown
# ADR-XXXX: <제목>

## 상태

Proposed | Accepted | Deprecated | Superseded by ADR-YYYY

## 배경

- 이 결정이 필요했던 상황, 제약, 문제.

## 결정

1. 무엇을 하기로 했는가(번호 목록).

## 근거

- 왜 그렇게 결정했는가. 검토한 대안과 트레이드오프.

## 영향

- 다른 ADR과의 관계, 이 결정이 건드리는 범위.
- 구현이 끝났다면 코드·테스트·README 등 상세 출처 경로.
```

## 불변 대상과 갱신 대상

- **불변**: "배경"/"결정"/"근거". 그 시점에 왜 그렇게 판단했는지의 기록이라 나중에 틀렸다고
  밝혀져도 본문을 고쳐 쓰지 않는다. 판단이 뒤집히면 새 ADR을 작성하고 이전 문서의 "상태"를
  `Superseded by ADR-YYYY`로 바꾼다.
- **갱신 가능**: "상태" 필드(라이프사이클 반영: Proposed → Accepted → Deprecated/Superseded),
  "영향" 절의 파일 경로 등 참조 정보(구현·병합 시점에 최신화). 정확성은 갱신 시점까지만
  보장되며, 이후 리팩토링으로 경로가 stale해질 수 있다는 점을 감수한 선택이다.

## 설계 로그와의 관계

대안 비교, 질의응답 로그 같은 상세한 설계 검토는 이 폴더가 아니라 저장소 추적 대상 밖의
작업 문서에 남기고, 완료 후 보관할 가치가 있다고 판단되면 요약만 이 폴더에 ADR로 남긴다.
ADR은 "무엇을, 왜" 결정했는지 git 이력만 보고 파악할 수 있는 최소 요약이어야 한다.
