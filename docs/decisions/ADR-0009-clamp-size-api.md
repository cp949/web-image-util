# ADR-0009: clampSize() min/max 범위 clamp API

## 상태

Accepted

## 배경

- `imageShortcut().maxSize()`(축소만 허용)와 `.minSize()`(확대만 허용)는 각각 단독으로만 동작하고,
  `resize()`는 체인당 1회만 호출 가능하다. 그래서 "원본이 너무 작으면 확대하고, 너무 크면 축소해서
  항상 `[min, max]` 범위 안에 들어오게" 만드는 요구(썸네일/아바타류에서 흔함)를 표현할 방법이
  없었다.
- 사용자 요청(그릴링, 2026-09-15)으로 설계를 확정했다. 이 ADR은 결정의 요약이다(영향 절 참조).

## 결정

1. `resize()`에 새 fit 모드 `clampFit`을 추가하고, `imageShortcut()`에
   `.clampSize({ minWidth?, minHeight?, maxWidth?, maxHeight? })`를 노출한다. 종횡비를 유지한 채
   스케일을 계산하며, CSS `clamp(min, 1, max)`와 동형이다(기준값 1 = 확대·축소 없음).
2. 4개 필드는 전부 optional이며 타입 레벨에서 "최소 1개는 있어야 한다"를 강제하지 않는다. 4개
   전부 비어 있으면 원본을 그대로 반환한다(no-op, 에러 없음) — 기존 `maxFit`/`minFit`의 "필드가
   하나도 없으면 에러"라는 관례와 의도적으로 다르다.
3. min 쪽이 요구하는 스케일이 max 쪽이 허용하는 스케일보다 커서 동시 만족이 불가능하면(예: 확대
   요구와 축소 요구가 상충), 에러를 던지지 않고 max 제약만 적용한 뒤 `console.warn`으로 무시된
   min 값·원본 크기·최종 크기를 알린다.
4. 이 모순은 원본 크기를 알아야 판정할 수 있어 렌더(출력 호출) 시점에만 검사한다.
   `.clampSize()`를 호출하는 시점의 조기 검사는 두지 않는다 — 그 시점에는 값 자체의 유효성(양수·
   유한수)만 검증한다.
5. `position`/gravity 필드는 두지 않는다 — `fill`/`maxFit`/`minFit`/`scale`과 같은 이유다(캔버스
   크기가 계산된 이미지 크기와 같아, 정렬 비율이 결과에 영향을 주지 않는다).

## 근거

- 에러 대신 경고 + 최선의 결과: "결과가 나와야 사용자가 원인을 이해하고 고칠 수 있다"는 요구가
  명시적이었다. 구조화된 경고 반환 채널(예: 결과 객체의 `warnings` 필드)은 이 출력 경로에 아직
  없어서, 새로 만드는 대신 `console.warn`을 택했다 — 침묵 실패를 막는 최소 장치.
- 충돌 시 max 우선: 상한을 지키는 쪽이 메모리 사용 측면에서 항상 더 안전하다는 판단.
- 타입 레벨 강제 포기: 필드가 4개라 "최소 1개" 를 판별 유니온으로 표현하려면 15분기가 필요하다.
  기존 2필드 방식(3분기)과 비용 대비 이득이 달라, 런타임 검증 하나로 수렴시켰다.

## 영향

- ADR-0004(resize placement)와 `position` 필드를 두지 않는 이유가 같은 계열(fill/maxFit/minFit/
  scale)에 속한다.
- 이 결정이 건드리는 범위: `ResizeConfig` 판별 유니온의 새 분기, resize 레이아웃 계산(스케일
  clamp 수식)을 소유하는 모듈, 호출 시점 값 검증을 소유하는 모듈, `imageShortcut()` 편의 메서드
  표면.
- 공개 API 표면: `clampSize()`, `fit: 'clampFit'`, `ClampFitConfig` 타입(루트 진입점 export). `isClampFitConfig`
  가드는 다른 fit 타입가드(`isMaxFitConfig` 등)와 동일하게 루트에서는 export하지 않는다.
